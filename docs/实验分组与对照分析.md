# 实验分组与对照分析

## 新增内容

- 总览的“实验名称、分组与备注”可给普通或 AI 对局设置标签。名称为空时自动生成，分组为空视为未分组。
- 批量实验支持同样的标签。实验记录详情中的“编辑实验标签”可整理新旧记录；继续推进普通对局不会覆盖用户编辑后的标签。
- 实验列表支持名称、分组、备注搜索，并按分组、模型、完整身份配置、知识模式、知识快照和座位 Agent 配置筛选。列表筛选不改变顶部本机整体概览。
- 新增“对照分析”页面：独立选择 A、B 条件和显示名称，生成指标表、比例图、配置摘要和样本回放链接。
- 支持对照汇总 CSV 与分析 JSON 导出。完整对局 JSON 继续通过实验记录页面导出，保留标签与回放数据。

## 设计原因与统计口径

服务端只读取当前浏览器拥有的存档，按具体对局筛选和统计。统计不参与模型提示、不调用模型，也不改变手动 AI 推进流程。

同组中同一个 gameId 的原记录和导入副本只计一次，优先原记录。两组之间重复的 gameId 会提示交叠，不自动将其当作独立样本。默认来源为本机运行，导入记录需主动选择。

匹配对局列表包含未完成记录，但所有指标只使用 `COMPLETED` 对局。被中断的批量实验中已经完成的局仍可统计。失败、中断及进行中的单局不进入胜率、行动质量、耗时和用量指标；其已消耗成本可在原记录详情查看。

| 指标 | 分子与分母 |
|---|---|
| 阵营胜率 | 对应阵营胜场 / 完成局数 |
| 平均轮次 | 完成局轮次之和 / 完成局数 |
| 好人投票命中率 | 实际好人身份投中狼人的合法票数 / 好人合法投票数；不含狼人自己的票或非法尝试 |
| 非法行动率 | `INVALID` 行动尝试 / 所有行动尝试 |
| 非法模型回复率 | 模型 JSON 格式或动作无效的回复数 / 模型调用次数 |
| 模型纠错重试 | 各行动 `max(0, apiCalls - 1)` 之和；用户重新点击的尝试分别记录，不归入内部纠错重试 |
| 平均模型决策耗时 | 调用过模型的行动耗时之和 / 该类行动数；含一次行动内的重试 |
| 平均接口请求耗时 | 请求耗时之和 / 模型调用次数 |
| 用量覆盖率 | 返回 usage 的调用数 / 模型调用次数 |
| 已报告 Token | 兼容接口实际返回的 Token 之和；没有任何 usage 时为空，不填零 |
| 平均已报告 Token | 已报告 Token / 返回 usage 的调用数 |

没有分母或没有用量数据时，页面显示“—”，CSV 保留空值。部分接口缺失 usage 时，已报告 Token 总量不能当作整组实际总消耗。非法行动与非法模型回复分别统计：LlmAgent 可以纠正第一次无效回复后提交合法动作。

差值统一为 B 减 A，比例差值使用百分点。数值高低不自动判定好坏。页面还提示模型参数、身份配置、座位 Agent、引擎版本不一致和组内混合配置；只有控制条件后才能解释某项改变的效果。当前提供描述性统计，不执行显著性检验、不自动生成因果结论。

知识模式分别为关闭、通用、角色、不使用 LLM、旧记录未知。旧 LLM 记录未保存知识元数据时不会被误归为关闭知识。知识快照筛选使用完整 SHA-256 值，界面显示前 12 位。角色模式保存的是开局启用知识快照，因此停用条目后快照版本可能变化。

## 推荐实验流程

1. 固定玩家配置、模型参数和座位控制方式，建立“无知识”“通用知识”“角色知识”三组。
2. 创建对局时填写分组，或在记录详情为已有对局补充标签。AI 对局逐人、逐阶段手动完成。
3. 在对照页面分别选择两组；检查模型、身份配置、知识版本与样本列表。
4. 查看每项指标的原始分母和模型用量覆盖率，再导出论文用汇总 CSV。
5. 平衡身份与座位分配，记录失败尝试。相同种子只保证规则引擎的随机过程，不保证模型输出一致。

导出会按展示结果对应的筛选条件重新统计当前记录，以文件中的生成时间为准。分析 JSON 包含筛选、配置摘要、指标和样本引用，可用于复查统计；它没有完整行动和事件，不能通过“导入实验记录”观看回放。观看回放仍需原实验完整 JSON。完整 JSON 导入会保留分组与备注。

## 兼容、存储与安全

旧存档没有 group、notes 时按空字符串加载，无须迁移或覆盖原文件。分组与备注和实验记录保存在同一个本地 JSON，沿用原子替换和浏览器访问凭据。更新标签先落盘，再更新内存，并检查名称、分组、备注的内容摘要 `metadataRevision`，避免多页面编辑覆盖。对局推进和批次进度不改变标签摘要，因此不会打断正在进行的标签编辑。

名称最多 80 字，分组最多 60 字，备注最多 2000 字。所有用户文本按普通文本展示；CSV 的用户文本沿用公式转义。标签更新与比较均不能读取其他浏览器的记录。模型密钥、Base URL 和访问凭据不进入分析导出。

## 测试方式

后端在 backend 运行 `.\mvnw.cmd test`，前端在 frontend 运行 `npm run build`。新增测试验证可手算的胜率与投票分母、缺失用量、完成局排除、导入副本去重、旧知识模式、访问隔离、标签跨推进与重启保留、JSON 往返、CSV 空值与公式转义。

手动检查：给两场对局设置不同分组，完成后在对照页各选一组；确认每组只列出匹配对局，并核对胜率。选择不存在的组合应显示零样本和“—”。编辑历史记录标签、重启后再查看，标签应保留。导出完整 JSON 并导入后，默认本机对照应排除副本，选择全部来源后应去重。

## REST 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| PATCH | `/api/experiments/{id}/metadata?revision=...` | `{name, group, notes}` 更新标签，revision 来自详情的 metadataRevision |
| GET | `/api/experiments/analysis/options` | 当前浏览器可选筛选条件 |
| POST | `/api/experiments/compare` | `{nameA, nameB, groupA, groupB}` 生成描述性对照 |
| POST | `/api/experiments/compare/export?format=csv|json` | 相同条件导出分析 |

组条件字段：group、model、config、knowledgeMode、knowledgeRevision、source、agentTypes。null 表示不限；空 group 表示未分组，空 model 表示无 LLM。source 默认为 LOCAL，也支持 SINGLE、BATCH、IMPORTED、ALL。config 格式为 `总人数/狼人/村民/预言家/女巫`；agentTypes 按座位顺序用 `/` 连接。

创建普通对局时新增 `experimentName`、`experimentGroup`、`experimentNotes`；创建批量实验新增 `group`、`notes`。这些字段始终是用户实验标签，不进入 AgentContext。
