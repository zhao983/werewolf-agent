# 实验记录与批量运行

本阶段提供实验数据采集与导出，以及 RandomAgent / RuleAgent 的固定种子重复试验。AI 对局仍由用户手动推进，每次行动同样记录调用次数、重试、失败与接口报告的 token 用量。

## 使用方法

1. 按 README 启动后端和前端，进入侧栏“实验记录”。
2. 输入实验名称、局数（1–200）、起始种子、身份数量和每个座位的 Agent 类型。
3. 点击“运行”，后台按 `startSeed + i` 顺序执行各局。页面显示进度和结果；“停止后续对局”会在当前局结束后停止。
4. 选择一条记录，查看汇总、座位身份和逐行动记录。点击“复用配置”后再运行，可重复同一组种子。
5. 导出完整 JSON、每局一行的结果 CSV，或每次行动尝试一行的行动 CSV。CSV 使用 UTF-8 BOM，便于 Excel 打开中文。
6. 换电脑分享时，将完整 JSON 复制到新电脑，在“实验记录”点击“导入 JSON 记录”，选择文件。支持版本 1 的导出文件（最多 25 MB），导入后即保存到新电脑本地。
7. 记录的对局结果表提供“对局回放”，支持上一条、下一条、自动播放和拖动时间线。身份可悬停查看，夜间内容可手动揭晓；重启后仍可使用。“对局历史”也从本地存档列出普通对局、批量对局和导入副本。

普通对局创建时会自动建立单局记录；点击行动按钮后更新，包括调用失败和非法回复。对局页提供“查看实验记录与导出”入口。

## 数据格式与指标口径

完整 JSON 的顶层为 `record` 与 `summary`。`record` 包含 `schemaVersion`、`engineVersion`、实验名称、来源、状态、配置、座位 Agent 类型、种子范围和各局数据。每局包含实际种子、座位身份、胜负、轮次、结构化行动尝试、完整游戏事件与 `observerNotes` 观战私有记录。私有记录只保存引擎已有的线索及截断后的决策摘要；API Key、模型服务地址、访问凭据、AgentContext、模型提示词和模型原始回复不进入导出。

| 字段 | 口径 |
|---|---|
| `completedGames / wolfWins / goodWins / averageDays` | 只计算完整结束的局；失败、中断、未结束的局不进入胜率和平均轮次分母 |
| `actionAttempts` | 引擎调用一次 Agent 算一次尝试；用户在失败后再次点击会新增尝试 |
| `validActions / invalidActions / failedActions` | 分别对应 `VALID / INVALID / ERROR`；仅合法动作会推进当前玩家 |
| `invalidReplies` | LLM 的 JSON 解析或动作校验失败次数；内部纠正重试也计入，不会被成功重试掩盖 |
| `apiCalls / apiFailures` | 所有真实模型请求及失败，包括内部重试；HTTP 错误、连接失败、空消息等算失败 |
| `usageReportedCalls` | 返回有效 `total_tokens` 的请求数；用量未知不能解释为零消耗 |
| `promptTokens / completionTokens / totalTokens` | 仅累加接口实际报告的对应字段，不估算。覆盖不全时是已知用量的小计，不能当作完整费用；没有报告用量的 CSV 单元格留空 |
| `decisionMillis / requestMillis` | 分别为 Agent 决策耗时和模型请求耗时；使用单调时钟，不包含人工等待 |
| `elapsedMillis` | 单局开始到结束的墙钟历时；手动局包含用户等待，不能与批量局直接比较 |

记录状态：`RUNNING`、`COMPLETED`、`CANCELLED`、`FAILED`、`INTERRUPTED`。停止和失败时，已完成的局可以导出；未执行的种子不会被伪造为失败局。后端启动时将旧的 `RUNNING` 记录标为 `INTERRUPTED`，不自动续跑或调用模型。

Random / Rule 在同一引擎版本、配置、座位 Agent 类型和种子下，身份分配、行动、事件与胜负可复现。对局 ID、创建时间与耗时不保证相同。外部 LLM 输出不受本地种子控制，LLM 对局不能宣称完全复现。论文对照建议固定经典 7 人规则，每次改变一个因素，分别比较各批次；页面的跨配置总览只用于展示。

## 保存与隐私

开发模式默认固定写入 `backend/data/experiments/<实验ID>.json`，不再随启动工作目录变化；打包运行使用 jar 所在目录下的 `data/experiments`。可通过环境变量 `WEREWOLF_DATA_DIR` 指定绝对目录，或使用 `werewolf.experiments.directory` 属性（相对路径以应用所在目录为基准）。页面显示实际保存位置。每完成一局批量游戏就保存一次，普通手动局每次推进后保存。文件包含用于授权的内部访问凭据，整目录应视为私有数据；Git 忽略规则已排除它。JSON / CSV 导出包含用户有权查看的身份及行动，分享前应自行选择需要的字段。

持久化记录、历史列表和回放可在后端重启后读取，但进行中的游戏内存状态无法恢复；当前没有续局功能。浏览器 cookie 保存一年，清除它或换浏览器后需显式导入备份文件建立本地副本。持久化文件应连同目录一起备份。损坏或不兼容的记录不会覆盖，启动日志会提示跳过的文件名。

导入支持 `{record, summary}` 导出格式和独立 `record`，本机备份中的 `{owner, record}` 也可显式导入。导入忽略外部 `summary` 和 `owner`，重新计算统计并绑定当前浏览器，生成新的实验编号，保留原对局编号但通过实验编号区分副本。导入来源标记为 `IMPORTED`；外部 `RUNNING` 状态转换为 `INTERRUPTED`，不会启动任务或调用模型。导入内容仅作为文件提供者的实验数据，格式校验不证明其真实性。重复导入会建立多个副本，全部不进入本机运行总览，单条导入记录仍显示自身统计。

导入校验版本、配置和身份数量、玩家与 Agent 类型、动作序号、状态、时间和指标范围，并限制文件大小、JSON 嵌套深度及事件数量。上传文件名不参与保存路径；只保存解析后的数据契约，API Key、未知字段和访问凭据不转移。回放页面把所有文字作为普通文本显示，完全独立于 Agent 决策输入。旧 JSON 未导出的模型原始思考和提示词无法从文件恢复；现有结构化行动和完整事件仍可回放。

“近期对局”和“对局历史”共用 `frontend/src/components/ObserverPanel.vue`，显示观战私有信息，可按玩家筛选且仅显示游标之前的记录。`frontend/src/observer.ts` 统一格式化并兼容旧文件。新记录由 `ExperimentRecord.GameSnapshot.capture` 保存原始 `observerNotes`，重启、导出和导入都保留它们；这些字段不进入 AgentContext。旧文件缺少该字段时优先从原浏览器仍有权限访问的运行中后端读取并一次性回填；升级期间临时缓存在同一浏览器，只有成功授权读取原存档后才使用，落盘成功后删除。已失去原始信息的旧文件只还原确定的狼队友、查验结果和合法行动，并明确提示无法恢复原始决策说明。`null` 表示旧存档缺失，空列表表示已保存但暂无私有记录。

## 接口

- `POST /api/experiments`：启动批次，正文示例 `{"name":"Random 基线","runs":20,"startSeed":42}`；省略配置和 Agent 类型时使用经典 7 人、全部 Random。
- `GET /api/experiments`：当前浏览器的记录摘要。
- `GET /api/experiments/{id}`：详细记录和指标。
- `POST /api/experiments/{id}/cancel`：停止后续对局。
- `GET /api/experiments/{id}/export?format=json|csv|actions`：下载完整记录、结果 CSV、行动 CSV。
- `POST /api/experiments/import`：multipart 文件上传，字段名 `file`；返回本机副本及重新计算的统计。
- `GET /api/experiments/storage`：实际保存位置与当前浏览器可见的记录数量。
- `GET /api/experiments/games`：当前浏览器可见的持久化对局历史摘要。
- `GET /api/experiments/{id}/games/{gameId}`：只读存档回放数据。
- `POST /api/experiments/{id}/games/{gameId}/observer-notes`：原浏览器回填旧普通对局缺失的观战记录；校验玩家、种类、时间线索引及文本长度，不覆盖已有数据，也不改写导入副本。

接口响应禁止缓存。创建时后端设置访问 cookie；读取、停止和导出需要原 cookie。批量请求中出现 LLM、空座位、非法数量或种子范围溢出时拒绝执行。

## 测试方式

```powershell
cd backend
.\mvnw.cmd test
```

后端测试覆盖混合基线重复试验、跨服务实例的记录恢复、未结束局统计分母、模型重试与失败用量统计、非法批量配置、停止和并发批次限制、跨浏览器授权、普通手动局逐步记录，以及 CSV 转义和密钥排除。

本次新增 `ExperimentStorage.java` 固定目录解析、`ExperimentImport.java` 导入校验；`ExperimentService.java` 保存副本并提供存档历史与回放，`ExperimentController.java` 提供上传与读取接口。前端 `StatsView.vue` 增加导入和目录提示，`HistoryView.vue` 读取存档，`ArchiveReplayView.vue` 实现只读时间线，原 `GameView.vue` 链接在后端重启后转到存档。沿用 JSON 原子写入，无须引入数据库。新增测试位于 `ExperimentImportTest.java` 和 `ExperimentControllerTest.java`，覆盖跨电脑导入、重启恢复、权限隔离、拒绝非法文件、不覆盖原数据、不信任外部汇总和不自动续跑。

```powershell
cd frontend
npm run build
```

页面验收：运行 20 局种子 42–61 的经典 Random 基线，导出两种 CSV 和 JSON；复用配置再跑一批，比较身份、行动和胜负；重启后端并用同一浏览器确认记录仍可读取。新浏览器不能打开原记录。模型对局创建后应保持暂停，并在每次点击时只推进原有的一名玩家。

跨电脑验收：导出 JSON，在新的浏览器或电脑导入，比较胜负、身份、事件和行动指标；进入对局回放，拖动到结尾再回到开局，确认存活状态随时间线重建。重启新电脑后端后继续查看导入记录和历史。导入错误 JSON 应显示错误且不增加记录。回放播放、暂停和拖动不应发送推进对局或模型请求。

观战面板验收：将两个入口的同一局时间线拖到相同位置，比较私有记录；点击身份牌或下拉筛选玩家，再回到开局确认没有提前显示未来摘要。新记录导出、导入并重启后端后，应仍能查看相同私有记录。旧 JSON 应有缺失提示，不能伪造原始说明。`ExperimentImportTest` 覆盖观战记录持久化与导入、旧字段兼容、一次性回填和非法记录拒绝；`ExperimentControllerTest` 验证访问隔离，普通对局接口不附带私有记录。现有引擎测试继续验证决策摘要不进入其他 Agent 的输入。
