# 本地角色策略知识库

## 新增内容与使用方式

1. 侧栏打开“本地知识库”，查看通用、狼人、村民、预言家、女巫分类。首次启动提供 7 条可编辑示例建议。
2. 选择分类后填写标题、正文、适用行动阶段、优先级与启用状态，点击“添加并保存”。已有条目支持编辑、启停和删除。
3. “导出 JSON”用于备份或分享策略；“导入 JSON”追加新编号，保留本机内容。重复导入也会新增条目，建议检查重复与启用状态。
4. 总览配置至少一名 LLM Agent 后，选择知识模式：关闭、仅通用、通用与对应角色。默认关闭；Random / Rule 不读取知识。
5. 创建对局时固定知识快照。每次 AI 行动由后端筛选策略，在观战私有信息下的“本局策略知识”中展开查看；存档回放和完整实验 JSON 同时保留快照及使用记录。

## 设计与信息隔离

- 游戏引擎继续只负责规则与合法动作。知识服务在创建会话的服务层绑定，LlmAgent 只持有通用条目和自己的真实角色条目。
- 根据当前阶段筛选，再按优先级从高到低排序；同优先级优先角色条目，再按编号排序。每步最多 4 条，编号、标题和正文合计不超过 2400 字符，JSON 格式开销另计。超出预算的条目跳过。
- 建议为普通文本，不解析 HTML，不读取外部文件，不执行其中的代码。提示明确策略不是本局事实，不能覆盖规则、可见信息、合法行动与 JSON 输出格式；程序仍独立验证模型动作。
- 用户可以看到全部库内容，但其他角色知识、观战面板和完整角色表不会随策略传入模型。角色所需的一般知识并不代表本局具体身份信息。
- 不会自动将对局发言、模型输出或导入实验的知识写回共享策略库。本局私有事实与长期记忆分别处理，长期 Memory 尚未实现。
- SHA-256 摘要用于标识条目内容版本，不代表作者身份或可信度。每步记录实际注入的条目编号；模型请求失败仍记录一次知识使用，内部纠错重试沿用相同条目。
- 实验导入校验快照摘要、角色、阶段、行动序号和条目引用。旧记录没有知识字段仍可观看，不补造历史策略。

## 本地存储与限制

默认保存 `backend/data/knowledge/knowledge.json`；与实验存档一样，以应用目录为基准，不随启动工作目录改变。打包后使用 jar 旁的 `data/knowledge`；`WEREWOLF_KNOWLEDGE_DIR` 可指定其他目录。

知识库由本机浏览器共享，属于用户维护的实验配置。接口默认只在本机开放；写入要求同源自定义请求头，不开启跨域管理。更新和删除校验编辑时的版本，防止另一页面修改后被旧内容覆盖。

限制：最多 200 条，标题 80 字，正文 1200 字，文件总量 512 KB，优先级 0–100。导入限制结构深度、字段长度、重复 JSON 键和编号，不采用上传文件名作为保存路径。保存使用同目录临时文件替换，成功落盘后才更新内存；损坏的已有文件会报错，保留原文件供修复。

## 代码位置

- `backend/src/main/java/com/example/werewolf/knowledge/`：条目契约、筛选、版本摘要与本地存储。
- `backend/src/main/java/com/example/werewolf/controller/KnowledgeController.java`：管理、导入导出接口。
- `backend/src/main/java/com/example/werewolf/service/GameService.java`：角色过滤、开局冻结、使用记录。
- `backend/src/main/java/com/example/werewolf/agent/LlmAgent.java`：策略注入与模型输出验证。
- `backend/src/main/java/com/example/werewolf/experiment/`：实验快照与导入校验。
- `frontend/src/views/KnowledgeView.vue`：知识管理页面；`frontend/src/knowledge.ts`：接口和类型。
- `frontend/src/components/KnowledgeUsagePanel.vue`：两个观战入口共用的知识使用展示。

## 测试方式

后端在 `backend` 运行 `.\mvnw.cmd test`；前端在 `frontend` 运行 `npm run build`。新增测试使用临时目录与模拟模型，不读取用户知识或调用付费接口。

手动验收：新增一条角色建议，刷新及重启后确认仍存在；编辑、启停、导入导出；创建开启知识的 AI 对局并手动推进，查看每步知识；中途修改库，旧对局应继续使用原快照；导出并导入实验，确认回放使用相同正文。比较关闭、仅通用与角色模式时，应保持模型与游戏配置一致，并平衡座位和身份分配。

上述建议均启用。优先级高于最初的示例建议，是为了在每步最多 4 条的限制下，优先提供本局暴露出的规则提醒；阶段筛选使狼人夜间袭击与白天队友核对分别占用一个角色条目位置。旧条目仍可编辑、启停。实际选择仍取决于启用状态、知识模式和其他用户条目的优先级。

同时，将原有“维护有依据的公开立场”和“谨慎使用有限药剂”中的程序标识改为狼人杀表述，保留其策略含义；初始化示例正文也同步调整。修改前的本机知识快照备份在 `backend/data/knowledge/backups/knowledge-before-ca238ffa-20261003.json`。

新增内容强调先辨别裁判事实、本人线索与玩家声明；允许狼人公开欺骗，但不应把自己的伪装当成真实队友关系。残局示例根据本项目的存活人数胜负规则推导，不适用于采用其他胜负规则的狼人杀变体。

使用方式：本机知识库已追加这些条目，刷新“本地知识库”页面即可查看。创建新的 LLM 对局时选“通用 + 对应角色知识”；只选“仅通用知识”会使用通用条目，选择关闭则均不读取。已有对局保留创建时的快照，新增建议不会改变过去的回放。

其他电脑可以通过知识库页面的“导入 JSON”导入分享文件。导入会追加新编号，请勿在已添加这些条目的电脑上再次导入，以免产生重复。

验收重点：刷新后条目存在且启用，保存的本地文件与管理接口一致；在各角色行动阶段检查实际选中的知识是否符合阶段和角色限制、数量与字符预算；旧条目保留。未调用真实模型验证改善幅度，因此不能宣称这些建议已经消除了规则错误，后续应比较相同配置下的事实错误率与动作失败率。

本次实际验证：7 条分享内容通过现有导入解析器；管理接口、导出和磁盘文件一致，原有 7 条均保留；使用项目实际筛选器检查了 33 个知识模式、角色与阶段组合，关闭模式无注入、通用模式不含角色条目、角色模式正确选中对应建议，白天三条新通用知识均被选中，且所有选择符合每步最多 4 条和 2400 字符预算。全部验证未启动真实模型对局。

## REST 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/knowledge` | 当前快照与保存目录 |
| POST | `/api/knowledge` | 新增条目，后端生成编号 |
| PUT | `/api/knowledge/{id}?revision=...` | 更新条目 |
| DELETE | `/api/knowledge/{id}?revision=...` | 删除条目 |
| GET | `/api/knowledge/export` | 导出知识 JSON |
| POST | `/api/knowledge/import` | multipart 字段 `file`，追加导入 |

写入请求携带 `X-Werewolf-Knowledge: 1`；创建对局请求的 `knowledgeMode` 为 `NONE`、`COMMON` 或 `ROLE`。知识快照与使用记录位于观战接口和实验快照的 `knowledge` 字段，不加入公共对局事件。
